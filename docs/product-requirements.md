# 门窗 AI 效果预览小程序产品需求文档

> 文档状态：MVP 需求草案
>
> 版本：v1.0
>
> 说明：本文依据现有前端页面与交互流程整理。未注明“已实现”的后端能力均为待开发需求；服务城市、价格、模型供应商和效果指标仍需业务或 POC 确认。

## 1. 产品背景

用户在更换门窗前，通常难以只靠型材样品或产品图判断安装到自己家后的效果。门店或销售也缺少一个低门槛工具，在上门测量前帮助用户理解窗型、颜色、玻璃和空间的搭配结果。

本产品通过“现场照片 + 窗户区域 + 可生产方案”生成改造前后对比预览，并将有明确意向的用户引导至预约量尺。

AI 效果图是方案沟通工具，不是施工图、尺寸图或最终交付承诺。实际生产必须以现场测量、结构评估和正式方案为准。

## 2. 产品目标

### 2.1 目标

- 让用户在较短流程内理解小程序的核心能力并完成首次预览。
- 生成结果必须绑定真实可生产的门窗方案和配置，而不是开放式任意绘图。
- 支持用户查看历史、收藏方案并基于效果结果预约量尺。
- 形成可追踪的生成成功率、有效结果率和预约转化漏斗。
- 对照片、联系方式和模型调用过程提供明确的隐私与安全保护。

### 2.2 非目标

- 不在 MVP 中自动输出精确尺寸、报价或施工图。
- 不保证 AI 预览与最终施工效果完全一致。
- 不在 MVP 中开放用户自由输入提示词。
- 不在 MVP 中提供在线支付、订单履约或施工进度管理。
- 不在 POC 结论前绑定某一家图像模型供应商。

## 3. 用户角色

| 角色 | 主要诉求 |
| --- | --- |
| 普通用户 | 快速看到自家门窗改造后的直观效果，保存偏好并预约咨询 |
| 门店/销售人员 | 使用可生产方案辅助沟通，获得用户意向和预约信息 |
| 运营人员 | 维护方案和配置、查看漏斗与失败情况；运营后台不在本次前端范围内 |
| 客服/量尺人员 | 获取预约联系方式、时间、地址和意向方案；工作台不在本次前端范围内 |

## 4. 核心用户旅程

```text
首页理解产品价值
  -> 上传现场照片 / 选择样例
  -> 框选需要改造的门窗区域
  -> 选择可生产方案、边框颜色和玻璃配置
  -> 确认并提交生成
  -> 查看生成进度
  -> 拖动对比改造前后效果
  -> 收藏方案 / 再生成一版 / 预约量尺
  -> 在个人中心查看历史、收藏和预约
```

关键中断恢复：用户退出生成中页面后，再次进入小程序应能通过任务历史恢复状态，不能因为页面销毁丢失任务。

## 5. 功能需求

### FR-01 微信登录与用户身份

- 小程序启动时调用微信登录并换取后端会话。
- 同一微信身份重复登录应对应同一用户。
- 登录失败时允许用户重试；游客策略待确认。
- 令牌失效时统一重新登录，不能让各页面分别处理一套认证逻辑。

验收标准：

- 首次和再次进入均能建立有效会话。
- 用户只能访问自己的照片、任务、结果、收藏和预约。
- 前端和普通日志中不存在 `session_key`、模型 API Key 等密钥。

### FR-02 首页与样例体验

- 首页首屏使用可拖动的改造前后对比图说明产品能力。
- 提供“上传照片”主入口，并提供样例体验作为低门槛次入口。
- 展示核心需求分类与精选方案，但不虚构服务数量、客户数量或准确率。
- 样例体验必须标识为样例，不得混入用户真实生成历史。

验收标准：

- 用户无需阅读说明即可找到主操作。
- 对比拖杆支持触摸操作，边界为 `0%~100%`，不会造成页面横向滚动。
- 样例与真实结果在数据类型和界面标识上可区分。

### FR-03 照片选择与上传

- 支持从相册选择或拍摄现场照片。
- 前端在上传前检查格式和大小，服务端再次执行可信校验。
- 上传时显示真实进度、取消或失败重试状态。
- 上传成功后获得 `photoId`，后续业务不依赖微信临时本地路径。
- 图片应自动纠正方向并移除 EXIF/GPS。

验收标准：

- 支持的图片能正常预览和上传。
- 超限、损坏、不支持的图片给出明确提示且不会进入生成流程。
- 上传失败不会伪装为成功，用户可重新选择或重试。

### FR-04 门窗区域框选

- 用户可移动和缩放选区，选区坐标以相对原图的归一化值保存。
- 系统提供默认选区；用户可以重置。
- 选区不能越出图片，且必须满足最小宽高和最小面积。
- 创建任务时服务端再次校验选区。

验收标准：

- 不同屏幕尺寸和图片方向下，同一选区对应相同原图区域。
- 越界或过小选区无法提交，并显示可理解的原因。
- 页面返回后选区仍可恢复。

### FR-05 方案与配置选择

- 展示可生产的门窗方案、适用场景、特点和图片。
- 每个方案提供后端配置的边框颜色和玻璃选项。
- 不可用方案或组合不能提交。
- 用户选择结果需在确认页完整展示。

验收标准：

- 前端只提交方案和选项代码，后端根据目录校验。
- 方案下架后，新任务不能继续使用；历史结果仍保留生成时快照。
- 颜色展示值与稳定代码分离，修改中文文案不影响数据。

### FR-06 生成前确认

- 确认页展示原图、框选区域、方案、边框颜色和玻璃配置。
- 明确提示“AI 生成效果仅供预览，实际以现场测量和施工为准”。
- 重复点击提交只能产生一个有效任务。
- 用户可返回修改照片、选区或方案。

验收标准：

- 请求包含完整选择数据和幂等标识。
- 连续点击、网络重试或页面恢复不会重复扣费或创建重复任务。

### FR-07 异步生成任务

- 创建任务后立即进入生成中页面，不同步等待模型完成。
- 任务状态为 `QUEUED`、`PROCESSING`、`SUCCEEDED`、`FAILED`。
- 页面展示阶段文案和进度；进度为后端可解释值，不制造虚假完成状态。
- 应用退到后台后减少轮询；重新进入后恢复查询。
- 可重试失败提供重试入口，不可重试失败引导重新上传或调整选择。

验收标准：

- 成功任务最终关联且只关联一个结果。
- 失败任务保留分类错误和 `requestId`，用户能得到下一步操作。
- 页面关闭再进入后能从服务端恢复任务状态。
- 超时、供应商失败和内容拒绝不会停留在永久加载状态。

### FR-08 效果结果与前后对比

- 结果页展示改造前和改造后图片，支持触摸拖动对比。
- 展示使用的方案、颜色和玻璃配置。
- 显示 AI 预览免责声明。
- 提供再次生成、收藏方案和预约量尺入口。
- 图片 URL 过期后可通过详情接口重新获取。

验收标准：

- 结果页只允许资源所有者访问。
- 前后图加载失败时有独立重试，不误导为生成失败。
- 对比交互在主流 iOS、Android 微信版本中可用。

### FR-09 历史记录

- 按生成时间倒序展示用户效果历史。
- 列表分页加载，包含前后缩略图、方案名和生成时间。
- 点击进入效果详情。
- 空状态引导用户创建第一次预览。

验收标准：

- 换设备或清空本地缓存后，登录同一账号仍能看到服务端历史。
- 样例体验与真实生成可区分。
- 下拉刷新和翻页不会产生重复项。

### FR-10 方案收藏

- 用户可在方案或结果页收藏、取消收藏。
- 收藏页展示当前仍可用的方案；下架方案可标识不可用。
- 收藏操作采用明确的添加/删除语义，支持网络重试。

验收标准：

- 重复收藏或重复取消不会反转状态。
- 多页面返回后收藏状态保持一致。
- 换设备后收藏可恢复。

### FR-11 预约量尺

- 收集联系人、手机号、服务区域、详细地址、预约日期、预约时段和备注。
- 预约应关联用户查看的结果或意向方案。
- 提交前获得隐私政策和联系方式使用授权。
- 提交成功展示预约编号、日期、时段和当前状态。
- 个人中心可查看预约记录。

验收标准：

- 服务端校验手机号、日期、时段和服务区域。
- 重复点击或网络重试不会创建重复预约。
- 手机号日志脱敏、数据库加密存储。
- 不在服务区域时明确提示，不能先显示成功再线下拒绝。

### FR-12 个人中心与数据清除

- 展示效果历史、收藏和预约数量及入口。
- 用户可发起清除照片、生成记录、收藏和预约数据。
- 清除前二次确认，并解释清除范围、不可恢复性和保留例外。
- 后端受理后清理前端本地草稿、令牌相关缓存和页面状态。

验收标准：

- 用户不能清除其他用户数据。
- 清除请求可审计，状态语义明确。
- 清除后列表不再展示对应数据；对象存储按声明时限完成清理。

## 6. 生成任务状态机

| 当前状态 | 允许进入 | 触发条件 | 用户界面 |
| --- | --- | --- | --- |
| `QUEUED` | `PROCESSING`、`FAILED` | 入队成功；排队失败或超限 | 等待生成，可离开页面 |
| `PROCESSING` | `SUCCEEDED`、`FAILED` | 供应商完成；超时、拒绝或处理失败 | 展示阶段和进度 |
| `SUCCEEDED` | 无 | 结果已转存并入库 | 进入结果页 |
| `FAILED` | 无 | 记录失败分类和是否可重试 | 显示重试或修改建议 |

重试应创建新任务并关联原任务，不能把旧失败任务直接改回处理中。

## 7. 页面与后端能力映射

| 前端页面 | 核心数据 | 后端能力 |
| --- | --- | --- |
| 首页 | 对比样例、精选方案 | 样例场景、方案列表 |
| 上传 | 用户照片 | 图片上传、删除 |
| 框选 | 归一化区域 | 创建任务时校验 |
| 方案选择 | 方案、颜色、玻璃 | 方案列表与详情 |
| 确认 | 完整生成参数 | 任务幂等创建 |
| 生成中 | 状态、进度、失败原因 | 任务查询与重试 |
| 结果 | 前后图、配置、免责声明 | 结果详情、签名 URL |
| 方案/历史 | 历史和收藏 | 分页结果、分页收藏 |
| 预约 | 联系方式、时间、意向 | 创建和查询预约 |
| 个人中心 | 数量和隐私操作 | 个人概览、数据清除 |

接口字段和示例见 [后端接口文档](./backend-api.md)。

## 8. 非功能需求

### 8.1 性能与可用性

- 除上传和模型生成外，服务端接口 P95 响应目标建议不高于 500 ms，最终阈值结合部署环境确认。
- 上传需要进度反馈；弱网失败可重试，但不能无限自动重试。
- 生成采用异步任务，轮询间隔由服务端返回并带退避策略。
- 列表接口必须分页；对象存储图片使用合适缩略图，避免首页下载原图。
- 生成服务需有超时、重试上限、熔断、限流和告警。

### 8.2 安全

- 所有资源查询都校验当前用户归属，不能只依赖前端传用户 ID。
- 文件上传执行大小、类型、解码和内容安全检查。
- 模型 API Key、微信密钥仅保存在后端密钥管理系统。
- 手机号、地址等敏感字段按最小权限访问，日志脱敏。
- 所有写接口防止重复提交；生成和预约必须支持幂等。
- 后台能力上线时另行设计角色权限和审计，不能复用普通用户接口直接开放。

### 8.3 隐私与数据保留

- 上传前说明照片将用于 AI 效果生成及必要处理。
- 原图、生成图和联系方式只用于已声明目的，不默认用于模型训练。
- 图片保存在私有对象存储；供应商临时图完成转存后尽快删除。
- 数据保留时长、清除完成时限、法定保留例外在上线前由业务与合规确认。
- 用户清除数据后，本地缓存和服务端数据必须按同一范围处理。

### 8.4 兼容与无障碍

- 支持业务确定的微信基础库最低版本及主流 iOS、Android 机型。
- 低端设备对毛玻璃和复杂动效可降级，但核心流程和文字对比度不受影响。
- 按钮、拖杆和表单需有足够触摸区域；错误不能只通过颜色表达。
- 页面在字体放大、长文案和小屏设备下不得遮挡核心操作。

## 9. 埋点与指标

### 9.1 关键事件

| 事件 | 关键属性 |
| --- | --- |
| `home_view` | 来源、是否新用户 |
| `upload_start` / `upload_success` / `upload_failed` | 图片类型、大小区间、失败码 |
| `selection_confirmed` | 选区面积区间，不上传原始坐标到分析平台 |
| `solution_selected` | `solutionId`、颜色代码、玻璃代码 |
| `render_task_created` | `taskId`、来源类型 |
| `render_succeeded` / `render_failed` | 耗时区间、失败分类、重试次数 |
| `result_view` | `resultType`、`solutionId` |
| `favorite_added` / `favorite_removed` | `solutionId` |
| `appointment_start` / `appointment_submitted` | 关联结果、时段；禁止上报手机号和地址 |
| `data_erasure_requested` | 清除范围，不含敏感内容 |

### 9.2 指标定义

- 上传成功率 = 上传成功次数 / 上传开始次数。
- 生成成功率 = 成功任务数 / 已结束任务数。
- 首次结果完成率 = 首次访问用户中成功查看结果的用户数 / 首次访问用户数。
- 结果到预约转化率 = 提交预约用户数 / 查看结果用户数。
- 单张合格图成本 = POC 人工判定合格结果的模型与基础设施总成本 / 合格结果数。

所有指标在正式评审前确定去重口径、时间窗口和测试账号排除规则。本文不预设目标数值。

## 10. AI 模型 POC 门槛

正式接入模型供应商前，至少完成：

- 选择 10–20 个真实可生产门窗方案及配置。
- 准备不少于 100 张已脱敏、覆盖客厅/卧室/阳台、不同光照和角度的现场照片。
- 统一评估结构保持、窗型正确性、产品一致性、边缘融合、生成成功率、耗时和单张合格图成本。
- 由产品、门窗业务人员和技术共同制定评分表，不能只看主观“好看”。
- 验证供应商是否允许所需地区、数据处理方式和商业用途，并在上线前重新确认价格与限额。
- 至少保留一个可替换的 `ImageModelProvider` 适配边界，避免业务流程依赖单一供应商字段。

POC 未通过时，不应通过放宽免责声明掩盖产品一致性问题；应调整输入约束、方案范围或模型方案。

## 11. MVP 范围与后续版本

### 11.1 MVP

- 微信登录
- 照片上传和区域框选
- 方案、颜色、玻璃选择
- 异步 AI 生成和失败重试
- 前后对比结果和历史记录
- 方案收藏
- 预约量尺和预约记录
- 个人概览与数据清除
- 基础埋点、监控、限流和隐私能力

### 11.2 后续候选

- 多个生成版本并排比较
- 用户评价生成结果是否接近预期
- 预约取消、改期和客服状态通知
- 初步报价区间
- 运营方案管理和人工审核后台
- 基于现场测量数据的正式方案衔接

上述候选不属于本次 MVP 验收范围。

## 12. 发布验收清单

- 核心流程在真实微信账号、真实手机和弱网环境完成烟测。
- 生成成功、失败、超时、内容拒绝和供应商异常均有明确终态。
- 连续点击和网络重试不产生重复任务或预约。
- 换设备后历史、收藏和预约可恢复。
- 未授权用户无法访问他人图片、结果和联系方式。
- 图片签名 URL 过期后可以刷新，不产生永久公开链接。
- 清除数据范围与隐私政策一致，并完成对象存储清理验证。
- 埋点不包含手机号、地址、原图 URL 或模型密钥。
- AI 免责声明在确认页和结果页可见。
- 真实可生产方案由业务负责人确认后才可上线。

## 13. 待确认事项

1. 首发服务城市、区县和不可服务区域。
2. 游客是否可以使用样例、是否可以生成真实照片。
3. 单用户每日生成次数、重试次数和限流规则。
4. 支持的图片格式、大小上限和最低分辨率。
5. 预约时段、提前预约天数、节假日规则和是否允许取消/改期。
6. 预约是否必须关联效果结果，还是允许仅关联方案。
7. 图片、生成结果、预约信息和审计记录的保留时长。
